go-chat — 45-Day Production Mastery Plan

From "solid Go boilerplate" → "I can ship and operate a production-grade Go service and understand every layer."

North star — go-chat deployed to a real cloud environment: WebSockets, multi-instance scaling, observability, CI/CD, secrets, load-tested, hardened. Plus a personal notes doc per phase.

See also: learning-checklist.html · boilerplate-checklist.md

Ground rules

Daily rhythm ~2.5–3h20 min read → 90 min code → 20 min notes → 10 min tick checklist. Adjust honestly if a day is shorter.
Never skip the notesThey are the compound interest. No notes, no memory. docs/notes-YYYY-MM-DD.md.
Commits are smallOne commit per topic minimum. Not one giant commit at end of week.
Stuck > 30 min? Ask.Write what you tried first, then ask. Don't burn a day.
Weekly review SundayRe-open checklist + notes. Redo shaky items. Update the progress log.
Non-negotiablesNever merge red CI. Never "come back to that later" without writing it down.
Phase 1 · Days 1–8

Go language fluency

The chat app will beat concurrency into you. But language basics you have to seek out. Do them first while your fingers are fresh.

Day 1Basics, values, types
  • Zero values for every type — print them all.
  • Value vs pointer semantics: Counter struct example.
  • Type conversion vs type assertion.
Deliverable — scratch/day01_types.go + notes.
Day 2Strings, bytes, runes
  • UTF-8 iterate with for i, r := range s vs s[i].
  • []byte ↔ string alloc cost, measure with -benchmem.
  • strings.Builder in action.
Deliverable — scratch/day02_strings_test.go with a benchmark.
Day 3Slices, maps, arrays
  • Slice header (ptr, len, cap) — observe with cap().
  • Reproduce slice aliasing gotcha with append.
  • Map random iteration order.
  • Benchmark prealloc vs grow.
Deliverable — scratch/day03_slice_gotchas_test.go.
Day 4Constants, iota, enums
  • Model chat MessageType with iota.
  • Add String() — become a Stringer.
  • Bit-shift iota for RoomPermission flags.
Deliverable — internal/message/type.go.
Day 5Interfaces deep dive
  • Study existing internal/user/service.go patterns.
  • Nil-interface-vs-holding-nil trap. Reproduce it.
  • io.Reader/io.Writer in a hasher.
  • Compile-time check var _ I = (*T)(nil) added to repo.
Deliverable — repo gains compile-time checks + trap notes.
Day 6Errors mastered
  • Wrap all repo errors with fmt.Errorf("...: %w", err).
  • Add Unwrap() to AppError.
  • errors.Join for multi-field validation errors.
  • Read the Go 1.13 errors blog post.
Deliverable — wrapped errors in repo, tests still green.
Day 7Control flow & closures
  • Type switch: func describe(x any).
  • Named returns + defer to annotate errors.
  • First-class fn: compose middlewares.
Deliverable — internal/middlewares/compose.go.
Day 8Generics
  • SliceMap[T,U any](in []T, f func(T) U) []U.
  • KeysOf[K comparable, V any](m map[K]V) []K.
  • Read the Go generics tutorial.
Deliverable — internal/genericutil/ used in repo.
Phase 2 · Days 9–14

Concurrency deep dive

Learn concurrency in isolated programs before wiring it into WebSockets. So when the hub explodes, you know why.

Day 9Goroutines + closure capture
  • Reproduce classic loop-var capture bug.
  • Fix by shadowing / passing as arg.
Deliverable — scratch/day09_goroutines_test.go.
Day 10Channels: unbuffered vs buffered
  • Producer/consumer, unbuffered.
  • Same, buffered — measure timing.
  • range + close semantics.
Deliverable — notes on when buffering helps vs hurts.
Day 11select + nil channel + default
  • 3-case select.
  • Set case to nil to disable dynamically.
  • default: for non-blocking.
Deliverable — small "event router" program.
Day 12Sync primitives
  • Race a counter → fix with Mutex. Run -race.
  • Benchmark RWMutex readers vs writers.
  • WaitGroup fan-out.
  • sync.Once lazy init.
Deliverable — benchmarks committed.
Day 13Concurrency patterns
  • Worker pool.
  • Pipeline.
  • Fan-in merge.
  • Done-channel cancel.
Deliverable — scratch/day13_patterns/, one file per pattern.
Day 14Context + goroutine leaks
  • Wire context.Context into worker pool.
  • Cause a leak; detect with runtime.NumGoroutine(); fix it.
  • Read Go blog: "Concurrency Patterns: Context".
Deliverable — "how to detect goroutine leaks" note.
